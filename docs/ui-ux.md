# UI/UX Direction

## 목적

이 문서는 `건강 기능식품 판단 MVP`의 화면과 사용 흐름을 정리한다.

기능 스펙은 `docs/superpowers/specs/`에 두고, 이 문서는 실제 사용자가 보는 화면의 원칙, 구조, 문장 톤, 컴포넌트 기준을 다룬다.

## 참고 방향: 토스식 단순함

토스를 참고하되 토스의 브랜드나 화면을 복제하지 않는다. 이 서비스에 가져올 것은 시각적 장식이 아니라 제품 원칙이다.

참고할 핵심:

- 사용자가 배우지 않아도 바로 쓸 수 있어야 한다.
- 한 화면에서 가장 중요한 행동이 분명해야 한다.
- 설명은 사용자가 지금 처한 맥락에 맞아야 한다.
- 질문은 쉽게 답할 수 있어야 한다.
- 사용자가 왜 이 결과가 나왔는지 알 수 있어야 한다.
- 한 화면은 한 가지 일을 해야 한다.
- 초기 MVP에서는 기능을 최소화한다.

이 서비스에 맞춘 해석:

- 사용자는 건강 지식이 부족한 상태로 들어온다.
- 사용자는 논문을 읽고 싶은 것이 아니라 구매 실수를 줄이고 싶다.
- 결과는 빠르게 말하되, 근거는 숨기지 않는다.
- 안전과 의약품 영역에서는 단정하지 않는다.

## 제품 인상

목표 인상:

- 앱처럼 가벼운 모바일 웹
- 쇼핑몰보다 차분한 판단 도구
- 병원 앱보다 덜 무겁고, 건강 광고보다 훨씬 신뢰감 있는 톤
- 정보가 많아도 첫 결론은 바로 읽히는 화면

피해야 할 인상:

- 제품 추천 랭킹 서비스처럼 보이는 화면
- 병원 문진표처럼 부담스러운 첫 화면
- 광고 검열 서비스처럼 공격적인 톤
- 전문가용 리포트가 처음부터 펼쳐진 화면
- 토스 화면을 그대로 베낀 듯한 색상, 아이콘, 문구

## UX 원칙

### 1. 첫 화면은 선택만 시킨다

첫 화면에서 사용자가 해야 할 일은 하나다.

> 지금 내가 확인하고 싶은 것이 무엇인가?

선택지는 3개다.

1. 제품 링크 체크
2. 목적 기반 상담
3. 광고/상품 설명 해석

각 선택지는 같은 크기의 카드 버튼으로 둔다. 사용자가 어떤 기능을 먼저 써야 하는지 고민하게 만들지 않는다.

### 2. 링크 입력이 가장 가벼워야 한다

제품 링크 체크는 MVP의 핵심 진입점이다.

기본 입력:

- 상품 링크

선택 입력:

- 먹으려는 목적
- 현재 먹는 영양제
- 현재 먹는 약

입력 순서는 링크가 먼저다. 목적과 복용 정보는 “더 정확한 판단을 위해 선택 입력”처럼 보이게 한다.

### 3. 결과는 결론부터 말한다

결과 화면의 첫 줄은 판단이어야 한다.

좋은 예:

> 눈 피로 목적이라면 이 제품의 구매 근거는 약합니다.

나쁜 예:

> 루테인은 카로티노이드의 일종으로 황반색소 밀도와 관련된 연구가 있습니다.

전문 정보는 중요하지만 첫 문장이 되면 안 된다.

### 4. 이유는 태그로 먼저 압축한다

결론 아래에는 이유 태그를 둔다.

예:

- 목적 불일치
- 함량 확인 필요
- 광고 맥락 부족
- 중복 섭취 확인 필요
- 섭취 시점 주의

태그는 사용자가 결과를 2초 안에 훑어보게 하는 장치다. 태그만 봐도 왜 결론이 나왔는지 방향이 보여야 한다.

### 5. 근거는 숨기지 말고 접는다

기본 결과는 쉬운 설명으로 충분해야 한다.

전문가 보기는 아래에 접힌 상태로 둔다.

전문가 보기에 들어갈 내용:

- 사용한 공식 출처
- 참고한 논문이나 메타분석
- 제품 페이지에서 추출한 성분표와 광고 문구
- 함량 계산
- 상호작용 주의 근거
- 섭취 시점 판단 근거
- 파싱 실패나 불확실한 정보

### 6. 안전 문장은 보수적으로 쓴다

구매 판단은 명확하게 말한다.

예:

> 이 목적이라면 추천하기 어렵습니다.

의약품, 질병, 복용 중단, 치료와 관련된 판단은 보수적으로 말한다.

예:

> 복용 중인 약이 있다면 의사나 약사에게 확인이 필요합니다.

절대 쓰지 말 것:

- 이 약과 같이 먹으면 안 됩니다.
- 복용을 중단하세요.
- 이 제품으로 치료할 수 있습니다.
- 이 성분은 무조건 효과가 있습니다.

## 화면 구조

### 홈

목표:

- 서비스가 무엇을 하는지 5초 안에 이해시킨다.
- 사용자가 바로 3개 모드 중 하나를 누르게 한다.

구성:

1. 짧은 제목
2. 한 문장 설명
3. 3개 모드 카드
4. 선택된 모드의 입력 패널
5. 결과 패널

홈은 랜딩 페이지처럼 길게 만들지 않는다. 첫 화면부터 제품을 써볼 수 있어야 한다.

### 제품 링크 체크

입력:

- 상품 링크
- 목적 선택 입력
- 현재 먹는 영양제
- 현재 먹는 약

결과:

1. 한 줄 결론
2. 이유 태그
3. 쉬운 설명
4. 함량과 섭취량
5. 섭취량 바꿔보기
6. 중복/상호작용
7. 섭취 시점
8. 근거
9. 전문가 보기

### 목적 기반 상담

입력:

- 목적
- 현재 먹는 영양제
- 현재 먹는 약

결과:

- 그 목적에 자주 연결되는 성분
- 실제 근거가 강한 영역과 약한 영역
- 흔한 마케팅 오해
- 제품을 고를 때 봐야 할 함량 기준

### 광고/상품 설명 해석

입력:

- 광고 문구 또는 상품 설명
- 선택 목적

결과:

- 맞지만 구매 판단에는 약한 말
- 함량 맥락이 빠진 말
- 연구 맥락과 사용 목적이 다른 말
- 질병 치료처럼 보일 수 있어 조심할 표현
- 제품 링크나 성분표가 추가로 필요한 이유

## 모바일 UX

우선순위는 모바일이다.

기준:

- 한 손 조작이 가능해야 한다.
- 주요 버튼 높이는 최소 48px 이상으로 둔다.
- 입력 필드는 한 화면에 너무 많이 밀어 넣지 않는다.
- 결과는 카드 하나에 다 넣지 말고 섹션으로 나눈다.
- 전문가 보기는 기본 접힘 상태로 둔다.
- 하단 고정 버튼은 초기 MVP에서는 쓰지 않는다. 화면이 복잡해진 뒤 검토한다.

## 데스크톱 UX

데스크톱에서는 앱 프레임을 넓게 늘리지 않는다.

권장 구조:

- 왼쪽: 입력 패널
- 오른쪽: 결과 패널
- 상단: 3개 모드 선택

데스크톱에서도 대시보드처럼 보이면 안 된다. 핵심은 “빠른 판단 도구”다.

## Visual System

### 색상

방향:

- 배경은 따뜻한 오프화이트
- 본문은 짙은 잉크색
- 주요 액션은 차분한 그린
- 경고는 과한 빨강보다 절제된 amber 계열
- 안전/주의/불확실성은 색상만으로 구분하지 않고 문구와 아이콘을 함께 쓴다.

기본 토큰 초안:

- Background: `#F5F2EA`
- Surface: `#FFFEF9`
- Text: `#17211B`
- Muted text: `#536157`
- Primary: `#315D3B`
- Primary soft: `#E7EFE1`
- Border: `#CBD5C8`
- Caution: `#A96B17`
- Caution soft: `#FFF3D6`

### 타이포그래피

원칙:

- 제목은 크고 명확하게
- 본문은 짧은 문단으로
- 버튼과 태그는 짧은 명사형
- 전문가 보기는 작은 글씨가 아니라 구조로 구분한다.

권장:

- 시스템 한글 폰트 우선
- 과한 디스플레이 폰트 금지
- 글자 간격은 기본값 유지

### 카드와 패널

카드는 다음에만 쓴다.

- 선택 가능한 모드
- 입력 패널
- 결과 섹션

페이지 전체를 카드 안에 넣지 않는다. 카드 안에 또 카드를 중첩하지 않는다.

Radius:

- 기본 8px 이하
- 태그는 pill 형태 허용

### 버튼

버튼 종류:

- Primary: 결과 보기, 다음 단계
- Secondary: 예시 입력, 다시 확인
- Text/Ghost: 전문가 보기 열기, 보완 입력

버튼 문구:

- 판단 결과 보기
- 예시 입력
- 전문가 보기 열기
- 섭취량 바꿔보기

피할 문구:

- 시작하기
- 경험해보기
- 더 알아보기
- 건강 여정 시작하기

## Interaction

필요한 움직임:

- 모드 선택 시 선택 상태가 즉시 바뀐다.
- 결과 생성 시 결과 패널이 부드럽게 나타난다.
- 전문가 보기 열기/닫기는 접힘 전환으로 처리한다.

피할 움직임:

- 튀는 애니메이션
- 배경 장식 움직임
- 결과가 늦게 나오는 듯한 가짜 로딩
- 건강 판단을 게임처럼 보이게 하는 효과

## UX Copy

### 기본 톤

- 짧게
- 단정하되 과장하지 않기
- 사용자의 구매 판단을 도와주는 말
- 의료 판단은 보수적으로

### 좋은 문장

> 이 목적이라면 구매 근거가 약합니다.

> 함량은 충분하지만, 현재 먹는 영양제와 성분이 겹칠 수 있습니다.

> 이 문구는 거짓이라기보다 함량 맥락이 빠져 있습니다.

> 복용 중인 약이 있다면 의사나 약사에게 확인이 필요합니다.

### 나쁜 문장

> 건강한 삶을 위한 최고의 선택입니다.

> 과학적으로 입증된 완벽한 솔루션입니다.

> 이 제품은 무조건 피하세요.

> 이 성분은 효과가 없습니다.

## Empty, Loading, Error States

### Empty

결과가 없을 때:

> 결과는 여기에 표시됩니다.

보조 문구:

> 링크나 목적을 입력하면 판단 흐름을 확인할 수 있습니다.

### Loading

실제 파싱이 들어가면 단계별로 보여준다.

- 상품 정보 읽는 중
- 성분표 확인 중
- 함량 계산 중
- 근거와 상호작용 확인 중

### Error

파싱 실패:

> 상품 페이지를 충분히 읽지 못했습니다.

다음 행동:

- 성분표 캡처 올리기
- 상품 설명 붙여넣기
- 제품명 직접 입력하기

에러는 실패가 아니라 보완 입력으로 이어져야 한다.

## Accessibility

기준:

- 모든 입력에는 라벨을 둔다.
- 버튼은 텍스트만 봐도 의미가 분명해야 한다.
- 색상만으로 상태를 전달하지 않는다.
- 포커스 상태를 명확히 보여준다.
- 모바일에서 터치 영역을 충분히 확보한다.
- 결과 섹션은 제목 구조를 유지한다.

## 적용 우선순위

다음 UI 개선은 이 순서로 진행한다.

1. 홈의 3개 모드 선택을 더 앱답게 정리한다.
2. 결과 화면을 결론 중심으로 압축한다.
3. 전문가 보기를 접힘 구조로 더 명확히 만든다.
4. 섭취량 바꿔보기와 섭취 시점 안내를 별도 섹션으로 정돈한다.
5. 파싱 실패와 보완 입력 흐름을 만든다.
